# R27.1.8 — r25 publication-lineage decoupling and full validator implementation reduction

## Purpose

Remove the last two r25 package-validator implementation blockers without
weakening the accepted r25.3.1.4 stock ADB-toggle publication lineage.

## Change

The publication verifier historically hash-locked the live
`r25.3.1` and `r25.3.1.1` validator implementation files. R27.1.8 moves that
lineage assertion to the canonical r25 validator profile registry:

- the historical validator SHA-256 remains recorded in `legacy_source_sha256`;
- the live revision path is a compatibility shim whose SHA-256 is separately
  locked by `compatibility_shim_sha256`;
- the publication verifier validates both identities and the canonical
  `COMPATIBILITY_SHIM` retirement state;
- the canonical validator remains the active implementation.

The original validator bytes are archived before replacement.

## Publication verifier cleanup

The forbidden-binary gate now checks Git-tracked files. If Git metadata is not
available, the fallback ignores generated `.git`, `.gradle`, `build`, and
`__pycache__` directories. This preserves the public/private boundary while
preventing local Android build outputs from causing false publication failures.

## Resulting retirement state

After R27.1.8:

- r25 validator compatibility shims: 12/12;
- Test 21 packager compatibility shims: 3;
- total compatibility shims: 15;
- remaining inbound dependency blockers: 27, all Test 21 packagers;
- container-compatibility blockers: 0;
- source-lock failures: 0.

No repository path is deleted in this phase.

## Scope

Host-only. No ADB, device, Bluetooth, Frida, Magisk, or network operation is
performed.
