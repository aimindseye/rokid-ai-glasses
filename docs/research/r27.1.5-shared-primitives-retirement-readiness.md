# R27.1.5 — Shared Canonical Primitives and First Retirement-Readiness Gate

## Purpose

R27.1.5 is the first consolidation stage that reduces duplicated implementation inside the canonical layer rather than only adding semantic dispatch.

It extracts common host-only primitives used by the canonical validator, evidence packager, source-contract dispatcher, tool-test runner, and repository catalog:

- SHA-256 file hashing and source-lock checks;
- JSON loading;
- subprocess execution with captured output and bounded timeout behavior;
- Python and shell syntax checks;
- regular-file/nonempty/no-symlink assertions;
- required-marker and forbidden-regex checks;
- SHA-256 sidecar writing;
- shared privacy patterns including dotted-version-safe standalone IPv4 detection.

The shared implementations live in:

- `scripts/research/canonical/primitives.py`
- `scripts/research/canonical/privacy.py`

## Retirement boundary

R27.1.5 distinguishes **independent canonical implementations** from canonical commands that still execute historical oracles.

| Family | Historical entries | Canonical execution | R27.1.5 disposition |
|---|---:|---|---|
| r25 package validators | 12 | independent canonical engine | `RETIREMENT_CANDIDATE` |
| Test 21 sanitized packagers | 30 | independent canonical engine | `RETIREMENT_CANDIDATE` |
| Test 21 source-contract checkers | 29 | executes locked historical checker | `NOT_RETIREMENT_READY` |
| Current Tests 19–21 tool-test suites | 38 | executes locked historical unittest | `NOT_RETIREMENT_READY` |
| Deferred Test 20 source contracts | 3 | historical-only/deferred | `PRESERVE_HISTORICAL` |
| Deferred Test 21 tool-test suite | 1 | missing historical fixture | `PRESERVE_HISTORICAL` |

`RETIREMENT_CANDIDATE` does **not** mean R27.1.5 deletes the file. It means the family has an independent, previously equivalence-qualified canonical implementation and can enter a later controlled wrapper/retirement phase after public/private lineage preservation is verified.

## Command

```bash
scripts/rokid-research retirement status
```

To write machine-readable reports:

```bash
scripts/rokid-research retirement status \
  --output "$HOME/Downloads/rokid-r27-1-5-retirement"
```

The output contains `retirement-readiness.tsv` and `summary.json`.

## Safety and preservation

R27.1.5 does not delete, rename, rewrite, or execute device-facing historical experiments.

```text
LEGACY_FILE_ACTION=NONE
REPOSITORY_DELETION=NONE
DEVICE_OPERATION=NONE
```

Historical source hashes remain part of the retirement gate. The later retirement stage must preserve exact source lineage before removing or replacing a revision-specific public path.
