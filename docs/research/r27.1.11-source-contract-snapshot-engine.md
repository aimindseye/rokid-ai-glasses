# R27.1.11 — Canonical Source-Contract Snapshot Engine and Checker Implementation Reduction

## Purpose

R27.1.11 moves the active Test 21 source-contract family from canonical *dispatch* to an independent canonical implementation. The historical checker filenames remain available for reproducibility, but the duplicated checker logic is no longer active.

## Scope

The current active Test 21 source-contract registry contains 29 profiles. R27.1.11 preserves all 29 original checker files in a private SHA-256-verified archive before replacing their live paths with compatibility shims.

The three Test 20 source contracts already classified as deferred historical contracts are out of scope and remain unchanged.

## Canonical contract model

The canonical engine uses `ACCEPTED_SOURCE_SNAPSHOT_V1`. Each profile records the accepted source closure observed by the historical checker on the qualified current tree:

1. exact SHA-256 identities for accepted source/artifact files read or existence-checked by the historical contract;
2. required repository directories where applicable;
3. explicit source-contract dependencies in place of historical checker-file hash chaining;
4. the archived historical checker SHA-256;
5. the active compatibility-shim SHA-256; and
6. the historical success stdout used by compatibility callers.

Across the 29 profiles the closure contains 288 file references and 27 explicit contract-lineage edges.

## Semantics

This is intentionally a stronger historical-revision contract than the old marker-oriented Python predicates. The historical checker might have tolerated a benign edit that retained its required marker strings; the accepted-source snapshot rejects any change to a locked accepted file until a reviewed successor contract is created.

That stricter behavior is intentional for historical reproducibility. It must not be interpreted as a general-purpose semantic validator for future edits.

## Compatibility behavior

Historical runners may continue to invoke paths such as:

```text
scripts/tests/check_test21_r3_3_4_2_6_1_2_source_contract.py
```

Those paths are now thin compatibility shims. On the accepted tree they preserve the historical success stdout exactly while delegating validation to the canonical snapshot engine.

Canonical use remains:

```bash
scripts/rokid-research contract check --list
scripts/rokid-research contract check --track test21 --revision r3.3.4.2.6.1.2
```

## Validation gates

R27.1.11 requires:

- 29/29 historical checker originals archived with their expected SHA-256 identities;
- 29/29 live checker paths locked to the generated compatibility-shim identities;
- 29/29 compatibility-shim results equal to the pre-migration historical success stdout;
- 29/29 canonical engine results equal to that same baseline;
- no historical checker execution from `source_contract.py`;
- all 38 current Tests 19–21 tool-test suites still passing;
- the one previously deferred missing-fixture suite remaining deferred;
- repository Markdown-link validation passing; and
- zero repository path deletion or device operation.

## Retirement state

After R27.1.11 the cumulative implementation-reduction status is:

```text
r25 validator compatibility shims: 12
Test 21 packager compatibility shims: 30
Test 21 source-contract compatibility shims: 29
retired compatibility-shim implementations: 71
current historical tool-test implementations still required: 38
deferred historical entries: 4
blocked source locks: 0

```

The next consolidation target is therefore the current historical tool-test implementation family, not the already-converged r25 validator, Test 21 packager, or Test 21 source-contract families.
