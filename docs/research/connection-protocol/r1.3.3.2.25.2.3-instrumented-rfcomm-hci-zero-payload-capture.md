# r1.3.3.2.25.2.3 — Instrumented Android RFCOMM HCI zero-payload capture

## Purpose

The accepted `.1.3` archive proves a single Android client RFCOMM lifecycle but
contains no proof-capable zero-payload counter. This deliverable performs one new
bounded attempt and derives explicit payload counters from the controller/host
HCI snoop stream.

## Proof policy

Full promotion requires all of the following in one metadata interval:

1. one Android client-side `connectSocket` lifecycle;
2. one conflict-free runtime tuple containing UID/PID, slot, port handle, SCN,
   DLCI, and MTU;
3. explicit transport open and close records;
4. exactly one btsnoop member with RFCOMM L2CAP channel discovery;
5. SABM/UA and DISC/UA boundaries on the target DLCI;
6. interval coverage with no btsnoop drops, truncation, or ACL reassembly gaps;
7. zero non-control UIH information bytes in both directions.

Logcat silence, callback absence, and configuration values such as
`max_rx_packet_size=0` never prove zero payload.

- `FAIL_RFCOMM_CLIENT_LIFECYCLE_CLOSURE`
