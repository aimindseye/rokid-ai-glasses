# r1.3.3.2.25.2.2.2.1 — Android RFCOMM Client-Semantic Recognition and Full Zero-Payload Closure Promotion

## Purpose

This repair re-analyzes an existing r25.2.2.2 private evidence archive without
contacting the phone or glasses. It closes the prior bounded outcome
`RFCOMM_SOCKET_OPEN_ZERO_PAYLOAD_RUNTIME_PARAMETERS_UNRESOLVED` only when one
attempt proves the complete Android client-side lifecycle.

## Promotion gate

One bounded attempt must contain all of the following:

- Android RFCOMM client semantics, including `on_cli_rfc_connect`,
  `is_server=false`/`is_server=0`, client role, outgoing/initiator, or
  BluetoothSocket client forms;
- one UUID and endpoint;
- probe UID and PID;
- RFCOMM slot `45`;
- port handle `29`;
- SCN `3`;
- DLCI `6`;
- MTU `990`;
- an ordered open record followed by a close record;
- explicit zero-payload counters.

Evidence is admitted only inside the exact metadata start/end interval. Native
records lacking an application attempt ID may join an explicit attempt only
inside its bounded client-connect lifecycle. Values from separate attempts are
never merged. Multiple qualifying attempts fail closed as ambiguous.

## Duplicate handling

The analyzer computes a semantic fingerprint from timestamp, event class, and
parsed fields. Identical records copied into both logcat and bugreport count once.
