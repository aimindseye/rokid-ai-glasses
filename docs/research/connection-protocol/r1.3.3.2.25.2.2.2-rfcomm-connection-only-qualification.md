# r1.3.3.2.25.2.2.2 — private-handoff RFCOMM socket-open qualification

## Objective

Consume the accepted private r25.2.2.1 cached-runtime handoff and perform one
independent RFCOMM socket-open qualification while Hi Rokid is disabled.

## Boundary

The Android client may create and connect one secure RFCOMM socket using the
private runtime address and runtime service UUID. It does not implement GATT,
does not obtain application data streams, does not transmit bytes, does not
consume bytes, and closes the socket after a bounded hold.

## Runtime gate

Full qualification requires the current independent run to demonstrate:

- one private-handoff connection request;
- a connected RFCOMM socket;
- socket closure;
- current runtime evidence for SCN 3, DLCI 6 and MTU 990;
- RFCOMM client ownership by the probe UID or PID;
- Bluetooth socket connected evidence;
- zero application payload reads and writes;
- no application data streams obtained;
- no GATT event.

The raw address, runtime UUID, source handoff and device logs remain private.
The publication contains only SHA-256 values and sanitized protocol facts.
