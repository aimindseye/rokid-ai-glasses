# r1.3.3.2.25.3.1 — stock ADB-toggle semantic-oracle repair and RFCOMM payload capture

## Purpose

This phase repairs the rejected r25.3 host-disappearance oracle. It uses the
accepted r25.2.3.2 HCI parser and the stock Hi Rokid Developer control to capture
two enable and two disable semantic transitions, attribute non-control RFCOMM
UIH information bytes on DLCI 6 to bounded action windows, subtract exact idle
signatures, and compute a repeated enable/disable differential.

## Semantic oracle

- Enable: `persist.vendor.adb=true`, stock switch checked=true, read-only glasses
  ADB control channel usable.
- Disable: `persist.vendor.adb=false`, stock switch checked=false, read-only
  glasses ADB control channel usable.
- Host ADB transport disappearance is not required.
- USB ADB configuration, `adbd`, and host-row presence are diagnostic context,
  not proxies for the stock setting.

## Safety boundary

- The operator uses only the stock Hi Rokid control.
- The research client does not toggle the setting, open an RFCOMM socket, send
  bytes, or replay captured payloads.
- No fastboot or partition operation occurs.
- Raw UIH bytes, bugreports, logcat, UI dumps, ADB rows, serials, and property
  samples remain private.
- Public output contains only reviewed semantic outcomes, directions, lengths,
  counts, hashes, differential positions, methodology, and limitations.
- The even action count restores the initial semantic state.

## Acceptance boundary

A passing run proves that repeated stock semantic enable and disable actions
produced attributable UIH payloads and a repeatable differential. It does not
prove command IDs, authentication, checksums, sequence fields, safe replay, or
independent control. Application framing remains a bounded candidate.
