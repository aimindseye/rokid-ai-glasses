This publication records a rejected physical qualification run. It does not
promote r25.3 to an accepted protocol result and does not supersede the accepted
r25.2.4 connection-only closure.

## What the stock toggle proved

The stock phone UI changed the glasses-side persistent vendor ADB property:

```text
enabled state:  persist.vendor.adb=true
disabled state: persist.vendor.adb=false
restored state: persist.vendor.adb=true
```

During the disabled state:

- `Settings.Global.adb_enabled` remained `1`;
- `adbd` remained running;
- the USB configuration remained ADB-capable;
- the already-authorized USB ADB transport remained alive; and
- no USB re-enumeration occurred.

The phone UI also reported the Developer Mode switch as disabled. The restore
step returned `persist.vendor.adb` to `true` without requiring transport
re-enumeration.

## Why the run was rejected

The original runner treated disappearance of the glasses from host ADB as the
required disable oracle. The stock implementation did not exhibit that
behavior. The runner therefore rejected a real stock property transition as a
failure before the payload-attribution phases could proceed.

The corrected semantic oracle must evaluate the stock state transition itself,
not require immediate loss of an already-established USB transport.

## What was not proven

The rejected run did not qualify:

- RFCOMM application payload bytes;
- UIH request or reply framing;
- command authentication or integrity fields;
- request IDs or correlation semantics;
- exact stock enable or disable command bytes; or
- any custom transmission.

No independent Developer Mode command was sent.

## Corrected r25.3.1 gate

The repaired runner should:

1. require the expected `persist.vendor.adb` transition;
2. capture and retain the phone UI switch state;
3. record, but not require, USB transport loss or re-enumeration;
4. restore `persist.vendor.adb=true` after each bounded phase;
5. continue to payload attribution only after the semantic transition is
   accepted; and
6. remain capture-only, with custom transmission disabled.
