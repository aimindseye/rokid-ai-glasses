# r1.3.3.2.25.2.2.2.1.1 — Android Bugreport Epoch-Timestamp Parsing, Explicit Timebase Provenance, and Real-Archive Attempt-Correlation Repair

## Disposition repaired

The preceding r25.2.2.2.1 analyzer returned zero attempts from the locked
r25.2.2.2 archive even though it counted 2,642 timestamped lines inside the
metadata interval. Its output recorded an inferred Android threadtime offset of
`-420` minutes and did not recognize Android bugreport records whose prefix was
Unix epoch seconds.

The rejected output is retained as a regression identity:

```text
Rejected analysis ZIP SHA-256:
47c13840ee3d7d0f17b00bfcd84859aa390fc84c72d6003e62518bef6bc76c9e

Locked source archive SHA-256:
35b209ab8243e68a26b3f32ab7f4bfcd111f88ece3d0be05c0a72e095dccf662
```

This repair does not assume that the corrected result will pass. It restores
eligibility of correctly timestamped evidence and then re-applies all closure
gates. The locked archive remains authoritative.

## Timestamp forms

The corrected parser supports:

- ISO 8601 timestamps with `Z` or an explicit offset;
- JSON timestamp and epoch fields;
- Android threadtime, such as `07-27 09:59:59.123 PID TID V ...`;
- Android bugreport epoch seconds, such as
  `1785160799.123 PID TID V bluetooth: ...`;
- Android bugreport epoch milliseconds.

Unix epoch values are UTC by definition. Android threadtime is local civil time
and is not converted until an auditable offset is resolved.

## Explicit timebase policy

Threadtime UTC conversion is permitted only through one or more consistent
sources:

1. a numeric UTC-offset field in run metadata;
2. an IANA timezone field in run metadata;
3. a bugreport property such as `persist.sys.timezone` evaluated at the exact
   run interval;
4. at least two unique semantic records appearing in both epoch-prefixed and
   threadtime-prefixed form, with a single non-tied 15-minute-aligned offset.

If sources disagree, the analysis fails closed. If semantic threadtime records
exist and no source resolves them, the analysis fails closed. The old technique
of trying offsets and choosing the one that yields the most RFCOMM matches is
prohibited and reported as:

```text
R25_2_2_2_1_1_SEMANTIC_OFFSET_MAXIMIZATION=NO
```

The private and public JSON outputs preserve the method, offset, timezone,
source references, pair count, and confidence.

## Record admission and duplicate removal

Records are eligible only when their canonical UTC time falls within the closed
metadata interval. The fingerprint used to collapse overlapping logcat and
bugreport copies contains:

- UTC timestamp rounded to milliseconds;
- parsed event flags;
- parsed fields other than source PID;
- normalized log message body.

The first retained record keeps its exact source and line reference. Duplicate
copies cannot inflate closure support.

## Same-attempt correlation

Application records with an explicit attempt ID establish the attempt. Native
records without that ID may be absorbed only inside the bounded lifecycle
window, before the next attempt anchor, and only when endpoint/handle evidence
is compatible. An inferred attempt is allowed only when a client-connect record
exists and no explicit attempt ID is available.

One accepted attempt must establish:

- Android client-side RFCOMM semantics, including `on_cli_rfc_connect`,
  `is_server=false`/`0`, BluetoothSocket client connect, or equivalent native
  client forms;
- runtime UUID and endpoint;
- probe UID and PID;
- slot `45`;
- port handle `29`;
- SCN `3`;
- DLCI `6`;
- MTU `990`;
- compatible open followed by close;
- explicit observed payload counters, all zero.

Conflicting identity, mismatched lifecycle handles, nonzero payload, incomplete
tuples, values split across attempts, or more than one qualifying attempt fail
closed.

## Publication boundary

Private analysis retains raw lines and source references. Sanitized publication
contains event fingerprints plus SHA-256-derived endpoint and UUID tokens. The
privacy gate rejects raw MAC addresses, raw UUIDs, concrete user-home paths, or
any raw identity value found during analysis.

## Offline-only boundary

The analyzer imports no socket, HTTP, subprocess, or request library. Package
validation rejects ADB, fastboot, Bluetooth CLI, curl, wget, or netcat commands
in the execution path. The source archive is read locally and its SHA-256 is
verified before output is created.
