# r1.3.3.2.25.2.2.2.1.3 — Attempt gate and zero-payload census repair

## Purpose

This additive offline repair preserves the accepted `.1.2` RFCOMM lifecycle
reconstruction and corrects two remaining defects:

1. attempt-level client, tuple, and open/close gates were projected only from a
   full-closure accepted attempt;
2. zero-payload discovery did not provide an archive-wide candidate census with
   explicit rejection diagnostics.

## Independent gate projection

Every reconstructed attempt publishes these gates independently:

- client-side RFCOMM semantic;
- complete expected tuple;
- expected value match;
- conflict-free identity;
- matching explicit open and close;
- bounded RFCOMM lifecycle closure;
- absence of a payload data event;
- absence of positive payload counters;
- explicit zero-payload proof;
- full zero-payload closure.

Failure of the final zero-payload gate cannot erase earlier proven facts.

## Archive-wide candidate census

Every text-like member, including members inside nested ZIPs, is scanned for:

- transmit and receive byte counters;
- aggregate payload-byte counters;
- payload/data callback counters;
- explicit zero-payload or no-payload assertions;
- positive payload assertions and counters;
- identity and timestamp fields usable for attempt correlation;
- configuration-only zero fields that must be rejected.

Each candidate receives a deterministic fingerprint, source references, scope
tags, correlation result, verdict, and one or more rejection or acceptance
reasons.

## Correlation and proof rules

A candidate may contribute to one attempt only when it is uniquely correlated
by metadata interval, timestamp, tuple identity, or a strong probe-summary scope
with exactly one lifecycle-qualified attempt.

Proof-capable zero evidence is limited to:

- an explicit zero/no-payload assertion;
- both transmit and receive byte counters equal to zero;
- an aggregate payload-byte counter equal to zero.

Callback count zero is corroborating only. `max_rx_packet_size=0`, MTU, buffer
sizes, queue depths, and other configuration fields are never treated as
transferred-byte evidence. Any positive counter, positive payload assertion, or
payload data event blocks full zero-payload promotion.

## Outcomes

- `PASS_FULL_ZERO_PAYLOAD_CLOSURE`: one lifecycle-qualified attempt plus
  proof-capable zero evidence and no contradiction;
- `PASS_BOUNDED_RFCOMM_CLIENT_LIFECYCLE_CLOSURE_ONLY`: one lifecycle-qualified
  attempt, but explicit zero-payload proof remains unavailable;
- `FAIL_RFCOMM_CLIENT_LIFECYCLE_CLOSURE`: no unique lifecycle-qualified attempt.

A bounded lifecycle-only result is publication-safe when clearly labeled. It is
not equivalent to zero-payload proof.
