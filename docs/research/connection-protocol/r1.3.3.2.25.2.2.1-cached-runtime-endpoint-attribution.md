# r1.3.3.2.25.2.2.1 — Cached Stock Runtime Endpoint Attribution

## Purpose

This phase performs **offline reanalysis** of accepted r25.2.2 stock-assist
evidence. It distinguishes the cached Classic runtime path from the provisioning
GATT path and produces a private connection-only handoff only when one endpoint
is uniquely closed by mutually supporting stock-app and Bluetooth-stack evidence.

## Attribution gate

A candidate must be introduced by a bounded Hi Rokid `connectBluetooth` line
containing a full runtime address and runtime UUID. The same endpoint suffix must
also be supported during the stock-assist interval by:

- BR/EDR ACL connection;
- successful SDP with SCN 3;
- client RFCOMM creation with SCN 3, DLCI 6, and MTU 990;
- RFCOMM socket ownership by the resolved Hi Rokid UID;
- stock-process Bluetooth socket connection on port 3;
- `readFromRfcomm`;
- successful CXR socket-protocol startup;
- stock Bluetooth status becoming available.

The public result contains only endpoint hashes and sanitized protocol facts.
The raw runtime address and runtime UUID appear only in the private handoff.

## Boundary

The phase invokes no ADB command and performs no Bluetooth connection, GATT
access, RFCOMM connection, stream access, application-payload operation, or
Developer Mode action. It only processes already-captured files.
