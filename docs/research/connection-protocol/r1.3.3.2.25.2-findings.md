# r1.3.3.2.25.2 — BLE 0x9301 Provisioning Read and Connection-Only RFCOMM Client

## Status

`IMPLEMENTATION_READY_FOR_DEVICE_QUALIFICATION`

This release implements the independently controlled sequence established by r25.1:

1. connect to the glasses over BLE;
2. discover service `00009100-0000-1000-8000-00805f9b34fb`;
3. read characteristic `00009301-0000-1000-8000-00805f9b34fb`;
4. parse the runtime RFCOMM UUID and Classic address in memory;
5. retain only SHA-256 identities and lengths in evidence;
6. close GATT;
7. open RFCOMM using the provisioned runtime UUID;
8. obtain neither socket stream;
9. send and read zero application payload bytes;
10. close the socket after approximately two seconds.

## Safety boundary

The client does not implement GATT writes, descriptor writes, RFCOMM stream access, CXR framing, account use, Developer Mode changes, Internet access, or hidden APIs. Hi Rokid must remain disabled throughout qualification. The glasses stay bonded; they are not unpaired or unbound.

## Promotion requirements

Live qualification is promoted only when the evidence proves:

- Hi Rokid disabled and not running both before and after the device action;
- successful `0x9301` read;
- runtime UUID acquired but not published;
- Classic address and account material not published;
- RFCOMM socket opened and closed;
- zero application payload reads and writes;
- no forbidden write/CXR/Developer Mode events.

SCN 3 and DLCI 6 logcat correlation is recorded when Android emits the relevant stack diagnostics, but socket qualification does not fail solely because production Bluetooth logging omits those diagnostics; r25.1 already closed that service/channel mapping.
