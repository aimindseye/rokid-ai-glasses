# R27.1.6 — Retirement Dependency Closure and First Legacy Reduction

## Purpose

R27.1.6 is the first phase that reduces a historical implementation rather than only adding canonical dispatch.

The R27.1.5 retirement gate identified 42 paths with independent canonical implementations. A second inbound-dependency review showed that implementation equivalence alone is not sufficient to remove all 42 paths safely.

## Dependency result

The 42 candidates split as follows:

| Family | State | Count |
|---|---|---:|
| r25 package validators | safe to reduce to compatibility shims | 10 |
| r25 package validators | blocked by r25.3.1.4 publication hash-lock | 2 |
| Test 21 sanitized packagers | blocked by historical source-contract/test/runner references | 27 |
| Test 21 sanitized packagers | no inbound reference, but whole-ZIP hash semantics differ from the deterministic canonical container | 3 |

No Test 21 packager is removed or rewritten in this phase.

## First implementation reduction

Ten r25 validator implementations are replaced in place by small compatibility shims. The historical path remains valid, but the actual validation logic now lives only in the canonical profile-driven validator.

Each shim:

1. resolves the repository root;
2. invokes the canonical r25 validator in quiet mode;
3. returns the canonical validation failure code when validation fails;
4. emits the exact historical PASS lines when validation succeeds.

The original validator bytes are archived and SHA-256 verified before replacement.

## Why two r25 validators remain historical implementations

`r25.3.1` and `r25.3.1.1` are still directly hash-locked by `scripts/research/verify_r25_3_1_4_publication.py`. They remain unchanged until that publication verifier is migrated to an explicit historical-source manifest.

## Why Test 21 packagers remain

Twenty-seven revision-specific packagers are still referenced by historical source-contract checkers, tool tests, or runners. Removing or rewriting those files would invalidate current historical-oracle execution.

Three early packagers have no live inbound reference, but the canonical packager intentionally creates deterministic ZIP containers. Member bytes are equivalent, but the overall historical ZIP hash can differ because older packagers inherited filesystem timestamps. They therefore remain until compatibility semantics are explicitly defined.

## Resulting retirement status

After R27.1.6 the intended classification is:

- retired implementation / compatibility shim: 10;
- blocked inbound dependency: 29 (27 Test 21 packagers + 2 r25 publication locks);
- blocked output-container compatibility: 3;
- still historical oracle: 67;
- preserve historical: 4;
- unblocked retirement candidates: 0;
- source-lock failures: 0.

## Scope

No repository path is deleted in R27.1.6. No device, ADB, Frida, Magisk, network capture, or phone operation is performed.
