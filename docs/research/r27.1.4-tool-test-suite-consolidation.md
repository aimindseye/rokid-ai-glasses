# R27.1.4 — Canonical Tool-Test Suite Registry and Current-Tree Equivalence

## Purpose

R27.1.4 consolidates the **invocation and lineage layer** for the historical `test_*_tools.py` family without rewriting or deleting the historical unittest implementations.

The current repository contains 39 historical tool-test suites across Tests 19, 20, and 21. Thirty-eight still execute successfully against the current source tree. One Test 21 suite is retained as a deferred historical contract because its synthetic obfuscated AAR fixture is no longer present in the repository.

## Canonical interface

```bash
scripts/rokid-research test run --list
scripts/rokid-research test run --track test21 --revision r3.2
scripts/rokid-research test run --track test21 --revision r3.3.4.2.6.1.3
```

The registry records, per historical suite:

- track and revision;
- historical test path;
- exact SHA-256 source lock;
- expected test count;
- execution class;
- bounded timeout;
- current/deferred status;
- required fixture paths for deferred suites.

## Execution classes

The canonical registry distinguishes:

- `HOST_LIGHTWEIGHT` — normal host-only Python/unit-test logic;
- `HOST_SUBPROCESS_FIXTURE` — host-side subprocess, parser, ZIP, or synthetic network/fixture exercises;
- `HOST_JAVA_FIXTURE` — host-side Java/Javac synthetic fixture tests.

References to ADB, Frida, or Magisk inside historical tests frequently validate **source safety boundaries**. The canonical runner itself contains no device-operation primitive and does not introduce device execution.

## Deferred historical suite

`test21 / r3.3.4.2.6.1.1` is retained as:

```text
DEFERRED_MISSING_FIXTURE
```

because the suite expects:

```text
fixtures/synthetic-obfuscated-client-l-1.0.1.aar
```

which is absent from the current repository. The historical test source remains hash-locked and preserved; R27.1.4 does not fabricate or substitute a fixture merely to produce a passing result.

## Equivalence gate

For each of the 38 currently applicable suites, R27.1.4 requires:

1. historical source SHA-256 lock passes;
2. canonical dispatch uses the exact historical test path, current Python interpreter, and repository working directory;
3. canonical execution returns success;
4. canonical execution reports the expected unittest count and `OK`;
5. no historical tool-test source is modified.

During package qualification, the 38 applicable historical files were also executed directly as the independent baseline. The installed verifier does not wastefully execute every slow Java/HTTP fixture twice; source locking plus the identical invocation contract makes the single canonical execution the current-tree equivalence gate.

The deferred suite must remain source-locked and its required fixture must remain absent for the specific deferred classification to be valid.
