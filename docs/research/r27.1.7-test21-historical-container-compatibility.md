# R27.1.7 — Test 21 Historical ZIP-Container Compatibility and Second Legacy Reduction

## Purpose

R27.1.7 removes the remaining output-container blocker for the early Test 21 `r3.1`, `r3.2`, and `r3.3` sanitized packagers without changing the newer deterministic canonical packaging policy.

## Historical container semantics

Those three historical packagers used Python `ZipFile.write(...)`. Consequently their whole ZIP SHA-256 incorporates source-file ZIP metadata such as filesystem modification times and mode bits. Re-running the same evidence later can therefore produce a different whole-container SHA even when every member byte is identical.

The canonical packager now has two explicit modes:

- `deterministic` — fixed ZIP metadata, used by the modern canonical path;
- `historical_source_metadata` — legacy `ZipFile.write(...)` semantics, used only by `r3.1`, `r3.2`, and `r3.3` compatibility profiles.

This preserves the historical contract instead of pretending those old ZIPs were deterministic.

## Second implementation reduction

The original three packager implementations are archived and SHA-256 verified before replacement. Their historical paths remain as compatibility shims delegating to the canonical packager with the appropriate revision profile.

No repository path is deleted.

## Remaining Test 21 blocker

Twenty-seven Test 21 packagers still have active inbound references from historical source-contract checkers, tool tests, or runners. They remain byte-unchanged in R27.1.7.

R27.1.8 should migrate those inbound dependencies to canonical profiles/manifests before any further packager implementation retirement.

## Scope

No phone, ADB, root, Magisk, Frida, network capture, or device operation is performed.
