# R27.2.7 — Canonical Test 19 network-privacy analyzer framework

R27.2.7 consolidates the shared host-only PCAPdroid CSV destination-analysis architecture used by the historical Test 19 r1 and r2 network analyzers.

This phase is **equivalence-only**. The tracked historical analyzers remain byte-unchanged as independent behavioral oracles:

- `scripts/tests/analyze_test19_network.py`
- `scripts/tests/analyze_test19_r2_network.py`

## Canonical interface

```bash
scripts/rokid-research network analyze-csv --list
scripts/rokid-research network analyze-csv --revision test19-r1 --csv /path/to/export.csv --output /path/to/result.json
scripts/rokid-research network analyze-csv --revision test19-r2 --csv /path/to/export.csv --output /path/to/result.json
```

The canonical core is `scripts/research/canonical/network_privacy_analyzer.py`; revision behavior is declared in `scripts/research/canonical/profiles/test19-network-analyzers.json`.

## Preserved semantic differences

The r1 profile classifies destinations only. A nonempty CSV with no public destination is `PASS`; any public destination, or an empty CSV, is `FAIL`. Its exit codes remain `0`/`4`.

The r2 profile additionally requires an application-identity column and separates custom-app traffic from Hi Rokid traffic. Hi Rokid public traffic is reported but does not fail the custom-app privacy gate. Its states remain:

- `PASS` / exit `0`: no custom-app public destination;
- `FAIL` / exit `10`: custom-app public destination observed;
- `BLOCKED` / exit `30`: CSV empty or app identity unavailable.

## Equivalence gate

`verify_r27_2_7.py` exact-locks both historical sources and runs five local synthetic CSV cases:

1. r1 local-only `PASS`;
2. r1 public-destination `FAIL`;
3. r2 custom-local + Hi-Rokid-public `PASS`;
4. r2 custom-public `FAIL`;
5. r2 missing-app-identity `BLOCKED`.

For every case it requires identical return code, stdout, stderr, and JSON output bytes between the historical analyzer and the canonical profile.

No PCAP capture, network access, device access, or privileged operation occurs in this qualification phase.

## Reduction boundary

Only after real-repository 2/2 equivalence is accepted should a later phase preserve the two historical implementations privately and consider compatibility shims. R27.2.7 itself performs no historical-file rewrite or deletion.
