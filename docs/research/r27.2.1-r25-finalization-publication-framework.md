# R27.2.1 — r25 finalization and publication-verification framework

R27.2.1 is the first implementation-consolidation phase after the completed R27.1 Tests 19–21/r25 retirement sequence. It targets thirteen tracked host-side connection-protocol scripts identified by the read-only R27.2.0 residual-family triage:

- seven private-evidence finalizers: `finalize_r25.py` through `finalize_r25_2_2_2.py`;
- six sanitized-publication verifiers: `verify_r25_1_publication.py` through `verify_r25_2_2_2_publication.py`.

This phase does **not** replace or delete those historical files. It introduces independent canonical engines and proves equivalence first.

## Canonical commands

```bash
scripts/rokid-research connection finalize --list
scripts/rokid-research connection finalize --revision r25.2.2.2 --run /path/to/run

scripts/rokid-research connection verify-publication --list
scripts/rokid-research connection verify-publication \
  --revision r25.2.2.2 \
  --publication /path/to/publication.json
```

## Finalizer profile boundary

The seven finalizers are not treated as interchangeable wrappers. Their profiles preserve revision-specific behavior including:

- manifest filename and JSON schema;
- whole-run versus required/optional evidence selection;
- manifest record representation (`sha256`, `size`, or `size_bytes`);
- archive membership;
- private archive suffix;
- deterministic versus source-metadata ZIP behavior;
- historical PASS/output markers.

The base `r25` finalizer retains its deterministic fixed-metadata archive semantics. Later historical finalizers retain source-file metadata behavior and are qualified by manifest equality, archive-member/content equality, ZIP metadata equality (excluding only the generated manifest write-time), and valid per-container sidecars.

## Publication-verifier profile boundary

The six publication-verifier profiles preserve release-specific privacy and semantic predicates, including combinations of:

- raw Bluetooth-address rejection;
- raw UUID rejection and the single allowed fixed UUID in r25.1;
- base64-like private-material rejection;
- recursive forbidden-key and 64-hex fingerprint rejection;
- zero-payload and no-independent-transport boundary assertions;
- exact release/schema and closure-field values;
- exact historical successful stdout.

The canonical verifier evaluates these predicates directly; it does not execute the historical verifier scripts.

## Equivalence gate

R27.2.1 requires:

- `7/7` finalizer profiles source-locked and behaviorally equivalent;
- `6/6` publication-verifier profiles source-locked and behaviorally equivalent;
- finalizer manifest and ZIP-member equivalence;
- required-file rejection equivalence where a finalizer has required inputs;
- publication privacy-rejection and semantic-rejection equivalence;
- zero legacy source changes;
- no repository deletion, device operation, or privileged operation.

Only after this gate passes on the real repository should a later phase consider replacing any of the thirteen historical implementations with compatibility shims.
