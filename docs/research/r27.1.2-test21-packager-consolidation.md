# R27.1.2 — Canonical Sanitized-Evidence Packaging Core and Test 21 Packager Migration

## Purpose

Consolidate the repeated Test 21 sanitized-result packaging mechanics without deleting or rewriting historical revision-specific packagers.

R27.1.2 represents **30** historical Test 21 packagers with one canonical implementation and declarative profiles. The 30th profile is the final accepted `r3.3.4.2.6.1.3` packager under `scripts/research/cxr/`, which was outside the earlier `scripts/tests/` family count.

## Canonical interface

```bash
scripts/rokid-research evidence package --list
scripts/rokid-research evidence package --revision r3.3.4.2.6.1.2 --evidence /path/to/evidence
scripts/rokid-research evidence package --revision r3.3.4.2.6.1.3 --evidence /path/to/evidence
```

## Shared implementation

The canonical packager centralizes:

- streaming SHA-256 calculation;
- internal `SHA256SUMS` generation and verification;
- deterministic ZIP member metadata;
- SHA-256 sidecar creation;
- fixed, exact, and historical all-file packaging policies;
- historical phone/token/MAC/PID and capture-extension gates;
- forbidden-filename gates;
- the final current privacy policy used by the accepted callback-Binder result.

The current privacy policy rejects user-home paths, emails, MAC addresses, bearer/JWT material, explicit phone-serial assignments, forbidden binary/capture file types, and valid standalone IPv4 addresses. A numeric window embedded inside a longer dotted revision such as `r3.3.4.2.6.1.3` is not classified as IPv4.

## Equivalence definition

Historical ZIP container hashes are not frozen because many old packagers inherited filesystem timestamps while the canonical engine deliberately emits deterministic ZIP metadata.

For migration purposes, a profile is equivalent only when:

1. the historical packager source SHA-256 matches its locked profile identity;
2. the historical packager succeeds on a safe synthetic evidence fixture;
3. the canonical packager succeeds on the equivalent fixture;
4. ZIP member names and member bytes are identical;
5. historical required PASS markers are observed where the historical script exposed them;
6. both ZIP sidecars validate;
7. the canonical implementation rejects an incomplete member set.

The final privacy implementation additionally carries regressions for the dotted-version IPv4 false positive and real standalone IPv4 rejection.

## Preservation boundary

R27.1.2 performs no historical packager deletion and no device operation.

```text
LEGACY_PACKAGER_ACTION=NONE
REPOSITORY_DELETION=NONE
DEVICE_OPERATION=NONE
```

Retirement of the historical packager files requires a later R27 phase after real-repository equivalence passes and revision lineage remains archived.
