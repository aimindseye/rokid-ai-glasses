# R27.1.1 — r25 Package Validator Consolidation and Equivalence Gate

## Purpose

R27.1.1 is the first actual implementation-family migration under the repository-wide R27 canonicalization program.

The R27.1.0 lineage census identified twelve tracked r25 connection-protocol package validators that repeatedly implement the same host-only validation primitives. R27.1.1 represents those validators through a single canonical engine and twelve declarative profiles.

## Scope

Historical family:

```text
scripts/research/connection-protocol/validate_r1_3_3_2_25_*_package.sh
```

Canonical implementation:

```text
scripts/research/canonical/connection_validator.py
scripts/research/canonical/profiles/r25-package-validators.json
```

Canonical operator interface:

## Validation primitives consolidated

The single engine implements:

1. required installed-file checks;
2. nonempty and no-symlink gates where historically required;
3. in-memory Python compilation without writing `.pyc` files;
4. shell syntax validation using `bash -n`;
5. exact SHA-256 prerequisite locks;
6. required semantic/source markers;
7. forbidden regex safety gates;
8. legacy PASS-marker preservation.

## Equivalence policy

R27.1.1 does **not** delete or rewrite the twelve historical validators.

The equivalence verifier executes each historical validator and its canonical profile against the same repository and requires:

- legacy return code = 0;
- canonical return code = 0;
- every historical PASS marker represented by the profile is observed;
- historical validator source hashes remain unchanged.

Only a later retirement stage may remove the revision-specific validator files.

## Safety boundary

This family is intentionally chosen as the first migration because it is host-only repository validation. The canonical validator does not run ADB, Fastboot, Frida, Magisk, Bluetooth capture, network capture, or any device experiment.

```text
DEVICE_OPERATION=NONE
LEGACY_FILE_ACTION=NONE
REPOSITORY_DELETION=NONE
```

## Legacy gate defect discovered during equivalence work

The R27.1.1 full-snapshot equivalence run exposed a historical validator defect in the `r25.3.1` and `r25.3.1.1` no-custom-transmission grep. The historical expression included `rfcomm.*write`, which also matches harmless analyzer source such as an `rfcomm-...md` filename followed later on the same line by `.write_text(...)`. Because the grep is used under an inverted shell command, the historical validator can still print PASS despite that incidental match.

The canonical profile repairs the **intended** safety check by making the RFCOMM write expression call-aware (`write(`) while retaining explicit checks for socket send/write calls, Bluetooth socket construction, package enable/disable, channel-probe `run-as`, Fastboot, and `dd` mutation patterns.

The historical validator files themselves remain byte-unchanged. This discrepancy is retained as lineage rather than silently editing old research code.
